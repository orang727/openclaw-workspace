## 三、工作流执行逻辑

### 3.1 入口参数

```json
{
  "trackWorkId": "1234567890"
}
```

### 3.2 执行伪代码

```python
def run_hangup_workflow(trackWorkId: str):
    # Step 1: 执行 Skill1 - 获取录音文件地址（内部完成跟单 ID 查工单号）
    skill1_result = call_skill(
        skill_name="get-call-record",
        params={"trackWorkId": trackWorkId}
    )
    
    # 检查是否获取成功
    if not skill1_result["success"]:
        # 中断处理：直接执行 Skill6
        skill6_result = call_skill(
            skill_name="generate-followup-task",
            params={
                "trackWorkId": trackWorkId,
                "intent_name": "",
                "intent_result": "",
                "followup_task_type": "挂起跟单",
                "interrupt_reason": skill1_result["fail_reason"]
            }
        )
        return skill6_result
    
    # 获取录音文件地址和工单号
    audio_url = skill1_result["audio_url"]
    servWorkId = skill1_result["servWorkId"]
    
    # Step 2: 执行 Skill2 - 识别意图
    skill2_result = call_skill(
        skill_name="dialogue-intent-analyzer",
        params={
            "trackWorkId": trackWorkId,
            "servWorkId": servWorkId,
            "audio_url": audio_url
        }
    )
    
    # 检查是否识别成功
    if skill2_result["status"] == "interrupted":
        # 中断处理：直接执行 Skill6
        skill6_result = call_skill(
            skill_name="generate-followup-task",
            params={
                "trackWorkId": trackWorkId,
                "intent_name": "",
                "intent_result": "",
                "followup_task_type": "挂起跟单",
                "interrupt_reason": skill2_result["interrupt_reason"]
            }
        )
        return skill6_result
    
    # 获取意图信息
    intent_name = skill2_result["intent_name"]
    intent_result = skill2_result["intent_result"]
    
    # Step 3: 根据意图执行不同分支
    if intent_name == "确认上门":
        # 执行 Skill3 跟单处理
        skill3_result = call_skill(
            skill_name="handle-track-work",
            params={
                "trackWorkId": trackWorkId,
                "intent_name": intent_name,
                "intent_result": intent_result
            }
        )
        # 执行 Skill4 改约
        skill4_result = call_skill(
            skill_name="modify-duty-time",
            params={
                "trackWorkId": trackWorkId,
                "intent_name": intent_name,
                "intent_result": intent_result
            }
        )
        return skill4_result
    
    elif intent_name == "用户询价":
        # 执行 Skill3 跟单处理
        skill3_result = call_skill(
            skill_name="handle-track-work",
            params={
                "trackWorkId": trackWorkId,
                "intent_name": intent_name,
                "intent_result": intent_result
            }
        )
        # 执行 Skill5 取消
        skill5_result = call_skill(
            skill_name="cancel-work-order",
            params={
                "trackWorkId": trackWorkId,
                "intent_name": intent_name,
                "intent_result": intent_result,
                "cancel_reason": "用户不需要了"
            }
        )
        return skill5_result
    
    else:
        # 其他意图：执行 Skill6 生成跟单
        skill6_result = call_skill(
            skill_name="generate-followup-task",
            params={
                "trackWorkId": trackWorkId,
                "intent_name": intent_name,
                "intent_result": intent_result,
                "followup_task_type": "挂起跟单"
            }
        )
        return skill6_result
```

## 十一、方案优化点

### 1）输入统一为跟单 ID
- 贴近真实业务入口
- 上游无需提前关心工单号
- 降低上游接入复杂度
- 更适合挂起跟单场景的任务驱动方式

### 2）Agent 更轻，Skill 更完整
- Agent 不再负责"先查工单号、再拿录音地址"
- 资源定位步骤收敛到 Skill1 内部
- Agent 编排更简单，状态机更稳定

### 3）获取录音 Skill 成为资源准备统一入口
- 对外只暴露一个能力：给我跟单 ID，我返回可识别的录音资源
- 更少的链路跳转
- 更少的 Agent 记忆负担
- 更少的接口拼装错误
